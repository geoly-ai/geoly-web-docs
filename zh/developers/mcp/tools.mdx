## 你能看到哪些工具

服务器只列出当前连接能用的工具。少了某个工具，说明它不在这次连接的范围内，不代表连接失败。

| 取决于 | 影响 |
| - | - |
| 组织范围 | 连接「全部组织」时多出 `list_organizations`，并关闭所有写入工具。 |
| 项目数 | 有多个项目可选时才出现 `list_brands`（它列出的是项目）。 |
| 读取授权 | 登录授权时没勾选的资源（品牌、提示词、竞品、引用、分析、诊断、信源、公开数据），读取它的工具就不出现。 |
| 写入授权 | 只有授予了写入权限的资源，才会出现对应的写入工具。 |
| 套餐 | 公开行业情报需要 Grow 及以上。三个公开信源工具所有套餐都免费。 |

## 通用参数

项目（Project）是 GEOly 的监测单元：一个项目监测一个自有品牌及其竞品。由于历史原因，项目 id 通过 `brand_id` 参数传递，`list_brands` 等工具列出的是项目。自有监测用的 `brand_id` 永远不是 `public_brand.id`。

项目维度的工具都接受下面三个参数，下文各工具的参数表不再重复。

| 参数 | 类型 | 必填 | 说明 |
| - | - | - | - |
| `brand_id` | string | 否 | 要查询的项目，传项目 id。不填时用连接绑定的项目，或组织里唯一的项目。项目 id 用 `list_brands` 获取（它列出的是项目）。 |
| `org_id` | string | 否 | 要查询的组织。只在连接覆盖多个组织时需要，组织 id 用 `list_organizations` 获取。 |
| `context` | string | 否 | 用一句话说明你想弄清楚什么。只随调用记录下来，不影响结果。 |

## 返回格式

每个工具都以文本形式返回一个 JSON 对象，以下约定对所有工具通用：

- **回显窗口**：带时间范围的工具会返回实际读取的窗口（`window`，业务日按 UTC+8）。引用数字时以它为准。
- **没准备好不等于 0**：`status: "not-ready"`、`kpiState: "computing"` 或某个比率为 `null`，都表示暂时没有可算的数据，绝不是 0%。
- **结果太长会截断并注明**：一页放不下时返回 `_truncated: true`，附 `_totalCount`、`_shownCount` 和告诉你怎么取剩余部分的 `_message`。
- **报错会说明下一步**：传了非法值时，报错里会列出合法值（比如项目已有的国家或 topic id）。报错和超时都不扣费。
- **额度**：计费调用会返回 `_quota` 回执，含本次费用和剩余额度。MCP 客户端也可以从 `_meta["geoly/quota"]` 读到它，从 `_meta["geoly/outcome"]` 读到调用结果。

## 费用

每个工具下的「费用」是单次调用的价格。按次计费的工具不受每页条数影响，需要多少就一次取够；按行计费的工具按返回的行数收费；部分工具在窗口超过 90 天时价格翻倍。剩余额度用 `get_quota`（免费）查询，每月额度见 [MCP 介绍](/zh/developers/mcp/introduction) 里的「套餐与 MCP 额度」。

## resolve_page_context

**Resolve Page Context.** Resolve what the user is currently looking at in the GEOly web app into an authoritative entity scope. Pass the browser URL verbatim. Returns pageKind, the entity id and its display title, the effective query parameters (country/language/platform/time window — already normalized and plan-gated exactly as the page renders them), and the tools most relevant to that page. Call this FIRST whenever the user refers to "this page", "this brand", "what I'm looking at", or asks about something on screen — then use the returned id and parameters verbatim in follow-up tools. Never search by name instead: same-named entities exist and you will answer about the wrong company. Unsupported or unknown pages return pageKind "unknown"; that is a normal response, not an error — answer from the selected text and what you already know.

**读写:** 只读 · **费用:** free. · **超时:** 15s

| - | - | - | - |
| `url` | string | 是 | The full URL of the GEOly page the user is currently viewing, taken verbatim from the browser. 1–4096 个字符. |

## resolve_my_brand_public

**Resolve My Brand Public.** Resolve YOUR OWN brand into the PUBLIC industry dataset — the bridge from your project's own brand to its public_brand twin. It resolves the project bound to your token (org-scoped tokens may pass the optional brand_id — a project id — within your org, or auto-resolve when the org has one project); it NEVER reads an arbitrary brand. bestMatch is the SAME decision the in-app /overview industry-profile card makes (2026-09-20): domain root is authoritative, then exact normalized name / match terms, then alias — each arm only accepts a single ACTIVE public brand that has public data; when several active public brands collide on the same root domain / name / alias the app fails closed and so does this tool: ambiguous=true, bestMatch=null, matched=false. matched is always bestMatch!==null. bestMatch.matchedBy ∈ domain|name|alias and carries availableLocales so you can immediately call get_public_brand (brand_id, or brand_ids to compare) WITHOUT a search_public_entities + get_public_coverage(view="locales") round-trip. candidates (≤5) is a looser heuristic context list; candidates[].matchedBy ∈ link|domain|name|alias — heuristic rows come from trigram search + the brand_public_brand_link override table (link|domain|name), and when matched, candidates[0] IS bestMatch and carries bestMatch.matchedBy (domain|name|alias, so alias can appear there). NEVER treat candidates[0] as your brand when bestMatch is null. matched=false and ambiguous=false means your brand is not in the public dataset yet (use the returned suggestion). Decision cached 5 min (ambiguity is re-probed every call). This is the FIRST call for any "how do I compare to my industry / category / competitors" question.

**读写:** 只读 · **费用:** free. · **超时:** 15s

### 参数

只有通用参数。

## get_brand_overview

**Get Brand Overview.** Brand MONITORING overview — the in-app /overview KPI row (five cells, same tracked-brand read model and filters) plus the per-platform table: aigvr.score = Visibility, aigvr.mentionRate = Mention rate, shareOfVoice.share = Share of voice, bestPlatform / worstPlatform = strongest / weakest platform.

**读写:** 只读 · **费用:** 3 credits per call — page size does not affect price; request the largest page you need. · **超时:** 45s

### 参数

| 参数 | 类型 | 必填 | 说明 |
| - | - | - | - |
| `time_range` | string | 否 | Window in whole UTC+8 business days, today included (today is partial): 7d / 30d / 90d / 180d = the last N business days. custom requires start_date (YYYY-MM-DD, UTC+8 business day); end_date optional; custom span clamped to 90 days and the end clamped to now. The response echoes window \{ timeRange, start, end, endBounded, businessDays \{ from, to \} \}: start / end are exact ISO-8601 instants — business day D starts at D-1T16:00:00.000Z (that day's first instant, NOT an earlier day); businessDays are the days actually counted, quote those. endBounded=false = end is just "now", not a filter. 可选值: `7d`, `30d`, `90d`, `180d`, `custom`. 默认: `"30d"`. |
| `start_date` | string | 否 | YYYY-MM-DD, only with time_range=custom — passed with any other range it is ignored and window.note says so. |
| `end_date` | string | 否 | YYYY-MM-DD, only with time_range=custom (inclusive). |
| `platform` | string | 否 | Platform code filter (chatgpt, perplexity, gemini, google_ai, copilot, google_ai_overview). Use "all" or omit for every platform. Must be a platform the brand is entitled to — an unentitled code is an error listing the ones it has, never a silent fall back to all platforms. 可选值: `all`, `chatgpt`, `perplexity`, `gemini`, `google_ai`, `copilot`, `google_ai_overview`. |
| `topic_ids` | string[] | 否 | Restrict every number to prompts in these topics (ids from get_topic_list; "_none" = prompts without a topic). Max 50 ids, each 1-64 characters; unknown ids are an error listing the valid ones. A filtered (topic_ids / country) KPI query over its 10s budget returns kpiState="unavailable" and no numbers at all — never unfiltered ones. 1–50 项. |
| `country` | string | 否 | Two-letter ISO country of the prompts (e.g. US), 1-8 characters. Restricts every number to that country; an unknown value is an error listing the countries this project has prompts in. 1–8 个字符. |
| `include_win_rate` | boolean | 否 | Win rate (Peec-style). true = also return winRate \{ rate, winRecords, rankCaliberRecords, excludedPreCutoverRecords, source, caliber \} + winRateState. rate = counted answers where YOUR brand is ranked first among the brands you track (untracked brands take no place) ÷ counted answers where your brand has a rank (%, 1 decimal; same window and filters as mentionRate). Own brand only. rankCaliberRecords = answers used; excludedPreCutoverRecords is always 0 (rank covers the whole history). winRateState is "ok". Default false (not computed, no winRate key). |

### 说明

- Counts the brands you track (own + added competitors) under the current configuration. aigvr.totalCount = counted answers; not-yet-counted ones are in trackedCounts.pendingRecords, never 0. kpiState="computing" = first count still running: no numbers (not 0), retry later.
- hasCompletedRecords=false (totalCount 0) = nothing counted in this window / scope: rates are 0 placeholders (page shows "—") — say "no data for this filter", never "0% visibility".
- Rates are record-weighted. avgPosition / rankedCount = your rank among TRACKED brands only. citationRate = answers mentioning you AND citing your domain ÷ answers where citation could be judged; null = no own domain. shareOfVoice = your mentioned answers ÷ (you + each tracked competitor); same-group brands excluded. kpiCaliber is always "board" (= get_brand_board ownBrand).
- platformStats: per-platform cells (aigvrScore, mentionRate, citationRate, avgPosition, totalMentions, mentionedCount, completed); only platforms with counted answers appear; best/worst null with &lt;2. keyMetrics.totalMentions = total own mentions; aigvr.top3Rate is tool-only.

Filters apply to every metric except hasPrompts; quote the echoed window (businessDays = UTC+8 days counted), platform and scope. Day-by-day: get_daily_trend; board: get_brand_board; citations: get_citation_overview.

## get_daily_trend

**Get Daily Trend.** Day-by-day KPI series of the in-app /overview trend chart. breakdown: "platform" (default, day × platform), "total" (day), "topic" (day × topic). Columns: completedRecords, mentionedRecords, mentionCount, brandCitationRecords, aigvr, mentionRate, citationRate (tracked-brand counts, same model as get_brand_overview) and sentiment \{positive, neutral, negative, mixed, unknown, scoredRecords, avgScore\} (daily derived layer; null = none, see sentimentNotReady); totals = the same per group over the whole window. completedRecords = counted answers (not-yet-counted / AI Overview not triggered left out); completedRecords 0 ⇒ null rates, not 0%. A missing (day, group) row = no monitoring ran.

**读写:** 只读 · **费用:** 1 credits per call — page size does not affect price; request the largest page you need. · **超时:** 20s

### 参数

| 参数 | 类型 | 必填 | 说明 |
| - | - | - | - |
| `start_date` | string | 是 | First day, YYYY-MM-DD — the UTC record-date key (= in-app business day − 1; get_brand_context.today.record_date_key is today's). Window ≤ 366 days; derived data starts 2026-04-13 (an earlier start_date ⇒ not-ready "day-key-epoch"). |
| `end_date` | string | 是 | Last day (inclusive), YYYY-MM-DD, same key as start_date. |
| `breakdown` | string | 否 | platform (default): one row per day × platform (platform + platformName). total: one row per day, all platforms together. topic: one row per day × topic (topicId + topicName; "_ungrouped" = prompts without a topic); topic_ids / country are not accepted with topic. 可选值: `platform`, `total`, `topic`. 默认: `"platform"`. |
| `platform` | string | 否 | Optional platform filter: chatgpt, gemini, perplexity, google_ai (Google AI Mode), google_ai_overview (Google AI Overview). "all" or omit = every platform. For a per-platform split use breakdown="platform" in ONE call — never filter per platform and add rows up. "google_aio" is NOT a valid code. 可选值: `chatgpt`, `gemini`, `perplexity`, `google_ai`, `google_ai_overview`, `all`. |
| `topic_ids` | string[] | 否 | Optional /overview topic chips (1–50 ids from get_topic_list / get_brand_context.topics, each ≤64 chars; "_none" = prompts without a topic, "_ungrouped" accepted). breakdown platform / total only. Unknown or blank ids are rejected — omit for all topics; selecting every topic = no filter (filters.scopeNote says so). 1–50 项. |
| `country` | string | 否 | Optional /overview country chip (ISO-2, e.g. US; ≤8 chars). breakdown platform / total only. Must be a country the project has prompts in; a project with one country = no filter. Omit for all countries. 1–8 个字符. |
| `compare_previous` | boolean | 否 | true = also read the equal-length window right before start_date: every row and totals row gains previous.* (incl. the day actually compared) and delta.* (current − previous; rates in percentage points), and window gains current / previous \{start, end, days, days_with_data\}. Rows are aligned by day position. Read days_with_data before calling a delta a trend. If the previous window is not built, the whole call is not-ready (reason "previous-window:…"). |

### 说明

CALENDAR: date is the UTC record-date key = the in-app (UTC+8) business day MINUS ONE, and start_date / end_date match that key; every row also carries businessDate — quote that one to people.

CALIBER: rates are record-weighted per day (1 decimal). Never simple-average daily rows into a window value — read totals, or get_brand_overview for the headline. citationRate = answers mentioning you AND citing your domain ÷ answers where citation could be judged (null = no own domain); brandCitationRecords / citationKnownRecords = its numerator / denominator. Citation URL counts: get_citation_overview.

status="not-ready" (reason): nothing substitutes. "day-key-epoch" (or "previous-window:…") = window starts before 2026-04-13: move start_date later; "flag-off:…" = not enabled — never retry those. "tracked-first-count-running" = first tracked-brand count still running (not 0): retry later; any other reason = not built yet: retry in minutes. compare_previous=true adds previous.* / delta.* and window.\{current,previous\}.days_with_data. One call fits ~4 weeks of "platform" (~10 days with compare) or ~6 months of "total"; longer windows keep the newest days (_capped).

## get_platform_matrix

**Get Platform Matrix.** Platform comparison matrix: rows × AI-platform columns. dimension="topic" returns monitored topics (up to 30). dimension="competitor" (default) returns your brand + automatically discovered competitors: by default the overall market Top 5 by metric, plus your brand pinned first when it is not among them (5 rows if your brand is in the Top 5, else 6 = your brand + 5 competitors); competitor_limit (1-20) = your brand + up to that many competitors, include_totals=true adds cross-platform totals to every row — competitor_limit=20 + include_totals=true with the default metric is the pre-0.7.0 get_competitor_overview (that name was removed in 0.7.0; a call returns a free TOOL_REMOVED notice until 2026-11-30). metric="citation" only re-sorts: its competitors are picked by entity id, not by citations.
